# منشئ التقارير الرسمية

اختر بطاقة «برنامج التقارير الرسمية» من بوابة `appcityimam` أو افتح `/official-reports` مباشرة دون حساب. يستطيع الزائر إنشاء التقارير وحفظها وتحريرها واستيراد Excel واستخدام أدوات الذكاء الاصطناعي المهيأة. تقارير الزائر مرتبطة بجلسة متصفحه بمفتاح عشوائي، وتختفي من قائمته بعد انتهاء الجلسة أو مسح بيانات المتصفح؛ احتفظ بنسخة PDF. لا تظهر له تقارير زائر آخر أو تقارير الحسابات. إذا دخل مستخدم بحسابه ترتبط تقاريره بحسابه وتبقى متطلبات بيانات الاعتماد والتحقق بخطوتين مطبقة عليه، ويظل المدير قادرًا على إدارة جميع التقارير.

لتفعيل الدخول المباشر على تثبيت موجود، ارفع الملفات المعدلة وشغّل:

```sh
php artisan migrate --path=database/migrations/2026_11_28_000001_allow_guest_official_reports.php --force
php artisan optimize:clear
```

تضيف الهجرة `guest_key` وتجعل `user_id` اختياريًا، مع الحفاظ على التقارير الحالية. يتطلب حفظ تقارير الزائر عمل جلسات Laravel وملفات الارتباط بصورة صحيحة. إذا كان الموقع يعمل عبر HTTP فراجع إعداد `SESSION_SECURE_COOKIE` ليتوافق مع البروتوكول المستخدم.

## التشغيل

شغّل `php artisan migrate --path=database/migrations/2026_11_26_000001_create_official_reports_table.php` لإضافة جدول `official_reports`. لا يتطلب البرنامج حزم Composer أو npm إضافية. يستخدم خط القاهرة المحلي ومخططات Canvas محلية دون CDN أو تعديل سياسة CSP. تبقى متطلبات المصادقة الثنائية وتغيير بيانات الدخول الآمنة مفعّلة كما في بقية البوابة.

المستخدم يرى تقاريره وحده، ومدير النظام يرى ويعدل جميع التقارير. لا توجد حاليًا دورة إرسال أو اعتماد أو توقيع إلكتروني، ولا فصل بحسب عضوية الشعبة؛ اسم الشعبة حقل يكتبه معد التقرير.

## إعداد التقرير

تعرض صفحة التقارير مسارين واضحين: تحليل ملفات Excel أو الإنشاء اليدوي، مع أعداد التقارير المتاحة، والتقارير المحدثة خلال سبعة أيام، والتقارير الشهرية. يمكن البحث بالعنوان أو الشعبة والتصفية حسب دورية التقرير؛ الأعداد والبحث يلتزمان بملكية المستخدم أو جلسة الزائر.

يتكون المحرر من ست خطوات: مصدر التقرير، البيانات والفترة، المحتوى والتحليل، المؤشرات والرسوم، التصميم، ثم المراجعة والإخراج. توجد أزرار للسابق والتالي ومعاينة قابلة للتوسيع. تُطوى الفقرات لتقليل طول الصفحة، ويمكن فتح كل فقرة لتحريرها. أزرار الملخص التنفيذي والنتائج الرئيسية وخطة الإجراءات تضيف هياكل فارغة، ويضم جدول الإجراءات المسؤول والموعد ومؤشر المتابعة.

تفحص شاشة المراجعة اكتمال العنوان والشعبة والمعد والتواريخ وعناوين الفقرات والقيم الرقمية، وتنبه إلى الفقرات والخلايا الفارغة وغياب الملخص والتوصيات واختلاف وحدات المؤشرات المشتركة في الرسم. عدد الفحوص المكتملة مقياس للاكتمال فقط، ولا يضمن صحة المصدر أو دقة الاستنتاجات. تمنع الواجهة الحفظ عند نقص المتطلبات الأساسية، وتبقى قواعد التحقق على الخادم مطبقة. يظهر أيضًا عدد الفقرات الظاهرة والجداول وصفوفها والرسوم. يمكن تنزيل نص التقرير للمراجعة؛ استخدم PDF للاحتفاظ بالتصميم الكامل.

زر «اقتراح ملخص من محتوى التقرير بالذكاء الاصطناعي» يرسل المحتوى الظاهر والمؤشرات والرسوم إلى المزود المهيأ عند الطلب فقط (حد 12000 حرف). تُعرض النتيجة للمراجعة ويضيفها الاعتماد كفقرة جديدة دون استبدال الفقرات الأصلية. يمكن استخدام اقتراح صياغة فقرة أو ملخص Excel إذا تجاوز التقرير الحد. حالة الحفظ في أعلى المحرر تميز التعديلات غير المحفوظة.

اختر النوع والفترة ثم أدخل بيانات الشعبة والعدد ومعد التقرير والمسؤول. تظهر الفقرات الست الرسمية تلقائيًا؛ يمكن تغيير عنوانها ونصها وترتيبها وإظهارها وإضافة فقرات وجداول وصفوف. لا تُملأ الأعمال أو المعوقات بأحداث افتراضية. تُدخل مؤشرات التقرير يدويًا ولا ترتبط تلقائيًا ببيانات التحليل الموجودة في النظام.

اختر أحد التصاميم الثلاثة وغير اللون والخط ونوع المخطط. تجب مقارنة مؤشرات من الوحدة نفسها، مثل عدد المعاملات المنجزة والمتبقية. احفظ التقرير ثم استخدم «طباعة / PDF» واختر الحفظ بصيغة PDF في المتصفح. هذا تصدير من المتصفح وليس توليد PDF على الخادم. وصف المرفقات للإشارة إليها فقط، ولا يرفع ملفات.

## القوالب

زر تصدير القالب ينزّل JSON بإصدار 1 يضم التصميم وعناوين الفقرات وأعمدة الجداول دون محتوى التقرير أو أرقامه أو هوية معده. الاستيراد يتيح تطبيق التصميم وحده أو استبدال الفقرات بعد تأكيد حذف بياناتها. تحفظ خصائص التصميم داخل كل تقرير بصورة مستقلة.

لا يستورد النظام HTML أو JavaScript أو CSS خارجيًا. يمكن تبادل ملفات JSON المتوافقة، بما فيها الملفات المعدة بمساعدة الذكاء الاصطناعي. لا يوجد اتصال تلقائي بمواقع قوالب متجددة؛ يحتاج ذلك لاحقًا إلى مزود محدد وواجهة API وترخيص مناسب وتحويل استجابته إلى مخطط JSON المعتمد.

## الذكاء الاصطناعي

أضف إلى `.env` في الخادم:

```dotenv
REPORT_AI_KEY=
REPORT_AI_MODEL=
REPORT_AI_ENDPOINT=https://api.openai.com/v1/chat/completions
```

اختر اسم نموذج متاح لحسابك ويدعم Chat Completions. يمكن استخدام مزود متوافق بتغيير endpoint من إعدادات الخادم. بعد تغيير الإعدادات شغّل `php artisan config:clear` أو أعد بناء cache الإعدادات وفق آلية النشر. المرجع: https://developers.openai.com/api/reference/cli/resources/chat/subresources/completions/methods/create

المفتاح لا يصل إلى المتصفح. الضغط على «اقتراح صياغة» يرسل نص الفقرة وتعليمات التحرير فقط إلى المزود، ولا يرسل التقرير كاملًا. يظهر الرد للمراجعة ثم يعتمد المستخدم الاقتراح صراحة؛ لا يُحفظ تلقائيًا. الحد 10 طلبات بالدقيقة لكل مستخدم. عند غياب الإعدادات يظل محرر التقارير متاحًا. الاتصال الحقيقي يحتاج مفتاحًا ونموذجًا صالحين؛ اختبارات المشروع تستخدم HTTP وهميًا ولا تُجري اتصالًا مدفوعًا.

## تقارير ملفات Excel

من محرر التقرير، اختر الملفات في بطاقة «تقرير تلقائي من ملفات Excel»، وحدد نوع التقرير أو اتركه تلقائيًا. اختر رقم صف عناوين الأعمدة (1–30) إذا سبقته عناوين كبيرة أو شعارات. اختر «قراءة الملفات وإنشاء التقرير»، ثم راجع ملخص النتيجة واضغط «تطبيق النتيجة على التقرير». التطبيق يستبدل المحتوى والتصميم بعد التأكيد؛ لا يحفظ التقرير تلقائيًا. بيانات المُعدّ والوحدة والتواريخ تبقى كما هي، لذا اضبط الفترة التي تغطيها ملفاتك.

يدعم XLSX وXLS بواسطة PhpSpreadsheet الموجود في المشروع. لا يفرض التطبيق حدًا ثابتًا لعدد الملفات أو حجمها أو عدد الأوراق والصفوف والأعمدة والجداول والفقرات والرسوم. يرفع المتصفح كل ملف بالتتابع على أجزاء صغيرة (512 كيلوبايت)، مع مؤشر تقدم وزر إلغاء، لتجنب إرسال الملف كاملًا في طلب واحد أو ربط عدد الملفات بحد max_file_uploads في PHP. تُقرأ كل ورقة على دفعات من 1000 صف لتقليل عدد خلايا المصنف المحملة في الذاكرة. تُقسّم الجداول الناتجة إلى أجزاء من 100 صف وستة أعمدة لتنظيم الطباعة فقط، دون سقف لعدد الأجزاء أو إسقاط بيانات. لم يعد نص الخلية محدودًا بـ1000 حرف. تبقى قواعد نوع الملف وبنية البيانات والتحقق من الملكية مطبقة. تُختصر عناوين الأعمدة إلى 100 حرف وعناوين الفقرات لتوافق بيانات التقرير؛ هذه قيود على نصوص العناوين وليست على عدد الأعمدة أو الصفوف.

يصنّف النظام التقرير وفق عناوين الأعمدة أو النوع المحدد، ويختار الألوان والتصميم. ينشئ رسوم توزيع الحالة أو القسم أو النوع، ومع غيابها يرسم اكتمال البيانات حسب الأعمدة (وهذا ليس نسبة الإنجاز). يُظهر المخطط حتى عشر فئات، مع تجميع البقية تحت فئات أخرى. تتضمن الأعمدة المناسبة مثل الكمية والتكلفة والراتب مجموعًا وأدنى وأعلى قيمة في وصف الجدول، ورسم مجموع مستقل بوحدة العمود، دون جمع المعرّفات أو التواريخ أو النسب. تُستبعد صفوف الإجمالي المعنونة في أول عمودين من هذه الحسابات، وتبقى في الجداول الأصلية. يجب مراجعة صفوف المجاميع غير المعنونة ووحدات القياس؛ لا يستطيع البرنامج استنتاج معنى كل تنسيق غير قياسي. لا تُحسب صيغ Excel مجددًا ولا تُشغل الروابط؛ تُقرأ النتائج المحفوظة وتظهر ملاحظة عند غيابها.

تُحفظ الرسوم مع التقرير وتظهر عند فتحه والطباعة، ومعها جداول بالقيم. يمكن تغيير عنوان الرسم ونوعه أو حذفه وتغيير لون التقرير. الرسوم لقطة من الحسابات وقت الاستيراد؛ تعديل الخلايا يدويًا لا يعيد حسابها. أعد الاستيراد عند تحديث المصدر. لا يقتصر التقرير على أول 12 مخططًا؛ تُحفظ جميع الرسوم. عند عدم وجود عمود تصنيف، تُقسّم رسوم اكتمال البيانات إلى مجموعات تشمل جميع الأعمدة.

اختيار «إضافة تحليل وتوصيات بالذكاء الاصطناعي» يستخدم إعدادات REPORT_AI الحالية. تُرسل إحصاءات السجلات وعناوين الرسوم (بما فيها اسم الملف والورقة) وقيم الفئات والمجاميع، دون صفوف الجداول الأصلية. لا تختَر هذا الخيار إذا احتوت هذه التسميات معلومات لا تريد إرسالها للمزود. الاستجابة نص تحليلي مقترح داخل التقرير، ولا تتحكم في حساب الجداول والأرقام. عند فشل المزود أو غياب الإعدادات يبقى التقرير المحلي جاهزًا مع تنبيه. تُجمّع الأجزاء في مساحة خاصة داخل storage/framework/report-uploads، مرتبطة بسر عشوائي في جلسة صاحب الرفع. تُحذف الملفات بعد محاولة التحليل أو الإلغاء؛ الرفعات المتروكة تُحذف بعد 24 ساعة بواسطة أمر reports:purge-uploads المجدول كل ساعة عند تشغيل Laravel Scheduler. الملفات لا تُنشر ولا يوجد مسار تنزيل عام لها. الطلب متاح للزوار أيضًا، وبحد خمسة طلبات في الدقيقة. تبقى متطلبات بيانات الاعتماد والتحقق بخطوتين مطبقة على المستخدم المسجل بحسابه.

عند النشر ارفع ملفات PHP وBlade وJavaScript وCSS المعدلة، وشغّل php artisan optimize:clear. لا توجد migration جديدة لهذه الزيادة في السعة. إعدادات PHP وخادم الويب وقاعدة البيانات وموارد الذاكرة والتخزين تحدد السعة الفعلية؛ إزالة الحدود البرمجية لا تعني موارد غير نهائية. تفاصيل الإعداد في القسم التالي.

## التحقق

### إعداد الخادم للملفات الكبيرة

ملف `docs/deployment/php-report-imports.ini` مثال لإعداد PHP الخاص بطلبات الويب: يسمح برفع الأجزاء، ويزيل سقف جسم طلب JSON ومهلة التنفيذ في PHP. طبّقه على خدمة PHP التي تشغّل الموقع ثم أعد تحميلها؛ وضعه داخل المشروع وحده لا يغير إعدادات الخادم. رفع الجزء الصغير لا يلغي الحاجة إلى السماح بطلب JSON كبير لحفظ التقرير.

في Nginx اضبط `client_max_body_size 0` لمسارات التقارير واضبط مهلة FastCGI أو الوكيل بما يناسب زمن معالجة البيانات. في Apache يمكن استخدام `LimitRequestBody 0` مع مراجعة مهلة الوكيل إن وجدت. راجع أيضًا مهلة `request_terminate_timeout` في PHP-FPM، والذاكرة المتاحة ومساحة `storage` وحدود حزم الاتصال في قاعدة البيانات مثل `max_allowed_packet` في MySQL. هذه إعدادات على الخادم خارج ملفات Laravel، ولا يغيّرها التطبيق تلقائيًا.

شغّل Laravel Scheduler المعتاد (`php artisan schedule:run` مرة كل دقيقة) لتنظيف الرفعات غير المكتملة، أو شغّل `php artisan reports:purge-uploads` دوريًا. تستخدم عملية الرفع أرقام أجزاء متسلسلة وتتحقق من الحجم المتوقع وملكية الجلسة قبل التحليل. عند انقطاع الشبكة أعد الرفع؛ لا يتوفر استئناف عابر لإعادة تحميل الصفحة.

يعرض المحرر حقول الجدول عند فتح فقرته فقط، مع تنقل بين مجموعات الصفوف والأعمدة. المعاينة موزعة على أجزاء مستقلة عن صفحات PDF. عند الطباعة تُعرض جميع أجزاء التقرير وجميع صفوفه، ويحتفظ الحفظ وتنزيل النص بجميع البيانات. المعاينة المصغرة للجدول اليدوي الكبير تعرض أول 100 صف مع ملاحظة واضحة؛ لا تحذف أي صف من التقرير. التقارير الضخمة جدًا تبقى خاضعة لذاكرة المتصفح وحدود الطباعة فيه. حد نص طلب مساعد الذكاء الاصطناعي مستقل عن سعة استيراد البيانات.

```sh
php artisan test
```

تشمل اختبارات القسم إنشاء التقرير وتعديله وحذفه، عزل المستخدمين، وصول المدير، تحقق المدخلات، وتعامل ربط الذكاء الاصطناعي مع غياب الإعدادات وأخطاء المزود.
